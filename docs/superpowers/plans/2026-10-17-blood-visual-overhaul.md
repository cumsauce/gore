# Blood Visual Overhaul Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the glyph-like blood art, flat colour, blob particles, silhouette-blind item blood and invisible NPC stains with organic, varied, surface-aware blood across every consumer.

**Architecture:** One pure `BloodAppearance` class owns all per-decal look (deterministic from decal identity — no protocol change). A rewritten stdlib atlas generator paints organic SDF splats with alpha falloff, rim/core depth and baked sheen. Particles stretch along velocity; item blood is masked by the item's real sprite silhouette; body stains project onto actual model cubes. Injuries (wound, body drips, accumulation, damage overlay) are Milestone 5, explicitly deferred.

**Tech Stack:** Minecraft 26.3 + Fabric (Loom 1.18.2), Java 25 (`/opt/homebrew/opt/openjdk@25`), JUnit 5, stdlib-only Python 3 for asset generation and pixel measurement.

**Spec:** `docs/superpowers/specs/2026-10-17-blood-visual-overhaul-design.md` (this plan implements D1–D7; the physics spec `2026-10-16-realistic-blood-design.md` still governs placement).

## Global Constraints

- Minecraft 26.3 / Fabric Loom 1.18.2 / **no Mixins**.
- **No shader path exists.** All rendering goes through `submitModelPart(ModelPart, PoseStack, RenderType, int light, int overlay, UvMapping[, int color])`; the trailing `int color` is per-submit ARGB tint (`0xFFFFFFFF` = untinted). `RenderPipelines.register` is private, `submitCustomGeometry` is inert.
- **No new dependencies.** Atlas and particle sprites stay script-generated by stdlib-only Python in `tools/`.
- **No network protocol change.** Per-decal appearance is a pure function of the decal identity; payloads and `Decal`/`GoreStain` codecs are untouched.
- `FabricParticleTypes.simple()` / `SimpleParticleType` carries **no data** — per-particle variation is client-side only.
- Existing atlas contract for legacy decals holds: cells 0–11 impact, 12–13 pools, 14 run, 15 bead. New art may **reshape** those cells but must keep those meanings; new cells start at 16.
- Pure logic classes live in `src/main/java/dev/lume/gore/` and are unit-tested in `src/test/java/dev/lume/gore/` (JUnit 5, `./gradlew test`).
- Visual verification only via `env JAVA_HOME=/opt/homebrew/opt/openjdk@25 ./gradlew runClientGameTest` (600000 ms timeout) → screenshots in `~/gore-run/clientGameTest/screenshots/`, measured with `tools/pixelstat.py`.
- Anti-goals still bind: no symmetric splats, no tails pointing toward the wound, no new deps, no shaders.

## Review Focus

1. **Legacy decals against a redefined atlas.** Cell 15 was redefined once already and silently changed old saves. — pinned by Task 2's `legacy_meanings` assertion (every legacy cell keeps its documented meaning) and by Task 1's `BloodAppearanceTest.legacyBornZeroRendersUntintedJitter` (legacy `born == 0` decals stay fully dry and only ever jitter within the blood palette).
2. **Translucent-layer blending and overlap.** New alpha falloff means decals, stains and particles now blend; overlapping stains and the translucent-terrain pass can double-darken or z-fight. — pinned by Task 3's game-test gate on an overlapping-decal region and Task 5's particle-over-stain screenshot.
3. **Item icons with non-square, off-centre or near-isotropic silhouettes** (bow, fishing rod, apple). The mask must not assume a centred shape and the dominant-axis PCA must not divide by zero on a symmetric blob. — pinned by Task 6's `SilhouetteTest.degenerateCovarianceFallsBackToAxis`, and Task 7's game-test gate on a bow-shaped item.
4. **Mob models with no named parts, one part, or no cubes at all** (slime = single part, allay = several unnamed). Projection must handle all three. — pinned by Task 8's `CubeProjectionTest` cases for zero-box, single-box and multi-box input.
5. **Determinism and RNG isolation.** The appearance hash must not consume `RandomSource`, or the seeded spray RNG that the game-test gates depend on drifts. — pinned by Task 1's `BloodAppearanceTest.doesNotConsumeRandomSource` and Task 5's repeated-run spray count gate.
